## Synopsis

Read-only views over the broker's image inventory. The controller reports
each container's image identity; the broker keys it by digest, not tag, so
two nodes that resolved `nginx:latest` differently show as two images.

```bash
kubectl kguardian images list [flags]
kubectl kguardian images get <digest> [flags]
kubectl kguardian images vulns <digest> [flags]
kubectl kguardian images sbom <digest> [flags]
kubectl kguardian images signers <digest> [flags]
kubectl kguardian images trust [flags]
kubectl kguardian images admission-policy [flags]
```

`list` and `get` show identity only; an image listed there is neither vetted
nor flagged. `vulns` and `sbom` show what scanners reported for the image,
from the supplychain component. `signers` shows who signed a digest and
`trust` which ImageTrustPolicies would deny what. See [vulns](/cli/vulns) for
vulnerabilities across the cluster.

## images list

Calls `GET /images` and prints one page, ordered by digest.

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `-n, --namespace` | string | Only images some workload in this namespace runs | all namespaces |
| `--repository` | string | Only this normalised repository, e.g. `docker.io/library/nginx` | all |
| `--limit` | int | Page size; the broker caps it at 500 | `100` |
| `--after` | string | Cursor for the next page (a digest) | first page |
| `-o, --output` | string | `table`, `json` or `yaml` | `table` |

```
DIGEST               REPOSITORY               TAGS         RUNNING  LAST SEEN
sha256:0123456789ab  docker.io/library/nginx  1.27,latest  3        2026-09-26T09:00:00
sha256:9f86d081884c  ghcr.io/acme/checkout    v4.2.0       0        2026-09-19T14:12:03
```

`RUNNING` is the number of workload containers running the digest now. `0`
means it is no longer running; the row stays until retention prunes it.
When more pages exist, the command prints the `--after` value for the next
page on stderr, so a piped table stays clean.

## images get

Calls `GET /images/{digest}` and prints the image and every workload
container that runs or ran it, running rows first.

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `-o, --output` | string | `table`, `json` or `yaml` | `table` |

```
Digest:      sha256:0123...cdef
Repository:  docker.io/library/nginx
Tags:        1.27, latest
Digest kind: repo
First seen:  2026-09-20T10:00:00
Last seen:   2026-09-26T09:00:00

NAMESPACE  WORKLOAD             CONTAINER  RUNNING  STATE                       LAST SEEN
shop       Deployment/checkout  app        true     running                     2026-09-26T09:00:00
shop       Deployment/canary    app        false    waiting (ImagePullBackOff)  2026-09-25T22:40:11
```

A digest the broker has never seen exits non-zero with `image ... is not in
the inventory`.

`-o json` and `-o yaml` print the broker's response unchanged, including
fields this CLI version does not know about. Global flags (`--kubeconfig`,
`--context`, `--broker-namespace`, `--broker-service`,
`--broker-token-file`, `--debug`) are listed in the
[CLI overview](/cli/overview).

## images vulns

Calls `GET /images/{digest}/vulnerabilities`: the findings scanners
reported for one image, deduplicated across sources, most severe first.
Findings come from Trivy Operator reports and, when the opt-in supplychain
matcher is enabled, from kguardian's own Grype matcher, which matches SBOMs.

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `--severity` | string | Only these severities, comma-separated: `critical,high,medium,low,none,unknown` | all |
| `--fixable` | bool | Only findings some source has a fix for (`--fixable=false`: only without) | all |
| `--source` | string | Only one source's report: `trivy-operator`, `grype` or `registry` | all |
| `--tier` | string | Only these tiers, comma-separated: `p0,p1,p2,background` | all |
| `--in-use` | string | Only these in-use states: `executed,loaded,unknown,installed_not_observed` | all |
| `--kev` | bool | Only KEV-listed (`--kev=false`: only those a source says are not) | all |
| `--epss-min` | float | Only EPSS at or above this probability (0-1) | off |
| `--fail-on` | string | CI gate, see below: `critical`, `high`, `medium`, `low`, or a tier `p0`, `p1`, `p2` | off |
| `--limit`, `--after` | | Page size (max 500) and cursor | `100` |
| `-o, --output` | string | `table`, `json` or `yaml` | `table` |

```
SOURCE          SCANNER       SCANNED              JOIN               SBOM TRUST  FINDINGS
grype           grype 0.87.0  2026-09-26T02:31:28  platform_manifest  unverified  1
trivy-operator  Trivy 0.58.1  2026-09-26T02:31:28  platform_manifest  scanned     3

TIER        SEVERITY  ID              PACKAGE     INSTALLED  FIXED   SCORE  KEV      IN USE        SOURCES
P0          HIGH      CVE-2099-30001  libfoo1     1.2.3-1    1.2.4   7.5    yes      loaded        trivy-operator
P1          HIGH      CVE-2099-10003  libexample  1.2.3      -       7.5    unknown  unknown       trivy-operator
Background  MEDIUM    CVE-2099-10002  tinyrouter  4.18.2     4.19.2  6.1    unknown  not-observed  trivy-operator

IN USE is from observed exec and shared-library capture: executed/loaded = a file the package owns ran;
unknown = no evidence either way (treat as potentially reachable, never as unused); not-observed = not seen
over a covered window, which is not proof the code can never run.
TIER: P0 = in use + (KEV or high EPSS) + exposed (no observed ingress counts as exposed, so a KEV finding
there is P0); P1 = in use + critical/high, or P0 factors without exposure; P2 = in use + medium/low, or
high with no fix and not exposed; Background = installed, not observed. "-" = not computed yet (never low risk).
```

- **No vulnerability data** means no source has reported on the image.
  That is unknown, not clean.
- **FIXED** lists every fixed version the sources give, in source order.
  None is picked, because text order is not version order.
- **KEV** `unknown` means no source said either way. Trivy never reports
  KEV, so this is not "not exploited".
- **JOIN** says how the report was matched to what runs: `image_id` and
  `platform_manifest` are exact, `workload_tag` is by tag only.
- **IN USE** and **TIER** are explained in [vulns](/cli/vulns#in-use-and-tiers).
  `unknown` is never "not used", and a KEV finding in a workload with no
  observed ingress is P0.

### CI gate: `--fail-on`

| Exit | Meaning |
|------|---------|
| `0` | No finding at or above the severity or tier |
| `1` | At least one finding at or above it. Findings whose severity no source knows (`UNKNOWN`) count; tiers already rank unknown in-use as in use. |
| `2` | The check could not run: the broker is unreachable, the port-forward or token failed, the broker returned an error, a flag was invalid, or `--fail-on p0/p1/p2` ran against a broker that does not report tiers. |
| `3` | No vulnerability data for the image. Unknown is never a pass. |

Every result prints a `gate:` line on stderr, so a pipeline can tell
"findings" (`1`) from "couldn't check" (`2`) from "no data" (`3`). Without
`--fail-on`, errors exit `1` as for any other command. The gate runs its own
query, so it sees every page, not only the one printed.

```bash
kubectl kguardian images vulns "$DIGEST" --fail-on high -o json > vulns.json
kubectl kguardian images vulns "$DIGEST" --fail-on p0   # P0 = in use, KEV or high EPSS, exposed
```

## images sbom

Calls `GET /images/{digest}/sbom`. Every source's SBOM is kept side by side
and listed with its trust level, weakest first:

| Trust | Meaning |
|-------|---------|
| `attached-unbound` | A bare document attached to the image in its registry |
| `unverified` | An in-toto statement naming the image; signature not checked |
| `scanned` | Trivy Operator's in-cluster scan |
| `verified` | Signature verified. The only level shown as signed. |

The components shown come from one SBOM: `--source` if given, else Trivy
Operator's, else another scanner's, and a registry SBOM only when it is the
only one.

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `--source` | string | `trivy-operator`, `grype` or `registry` | the broker's choice |
| `--limit`, `--after` | | Components per page (max 500) and cursor | `100` |
| `-o, --output` | string | `table`, `json`, `yaml` or `cyclonedx` | `table` |

```
SOURCE          FORMAT     TRUST       SIGNED  COMPONENTS  SCANNED
trivy-operator  CycloneDX  scanned     no      3           2026-09-26T02:31:28
registry        SPDX       unverified  no      2           2026-09-26T02:31:28

Components from trivy-operator (trust scanned):
NAME        VERSION  TYPE  LICENSES  PURL
fastparse   2.1.0    npm   MIT       pkg:npm/fastparse@2.1.0
tinyrouter  4.18.2   npm   MIT       pkg:npm/tinyrouter@4.18.2
colorize    1.4.0    npm   MIT       pkg:npm/colorize@1.4.0
```

`-o cyclonedx` writes the broker's CycloneDX 1.5 JSON export of that SBOM
(`GET /images/{digest}/sbom/cyclonedx`) to stdout, with the source, join and
trust in `metadata.properties`:

```bash
kubectl kguardian images sbom "$DIGEST" -o cyclonedx > sbom.cdx.json
```

A listed component says nothing about whether it is loaded at runtime.

## images signers

Calls `GET /images/{digest}/attestation`: who signed one image digest, as
kguardian's signature discovery found it (needs
`supplychain.signatureDiscovery.enabled`).

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `--fail-on` | string | CI gate: `invalid`, `unsigned` or `unverified` (see below) | off |
| `-o, --output` | string | `table`, `json` or `yaml` (the broker's answer, unchanged) | `table` |

| Verdict | Meaning |
|---------|---------|
| `verified` | A signature verified for the signer shown: a keyless identity (certificate SAN via OIDC issuer) or a configured key (name and sha256 of the key). |
| `key_signed` | Signed with a public key kguardian was not given. The signature was **not** checked, so its signer is not known. |
| `unsigned` | No signature, and every lookup answered. |
| `invalid` | Signatures exist and none verified. |
| `unknown` | Could not be checked (`REASON` says why: `registry_auth` for a private image, `rate_limited`, `timeout`, ...). Not unsigned. |

<Warning>
**Verified is not trusted.** Anyone with a Fulcio identity or a key can
sign, and anyone who can push to the repository can attach a signature.
Whether the signer is one you accept is what an
[ImageTrustPolicy](/concepts/image-trust-policy) decides: see
[`images trust`](#images-trust).
</Warning>

An unverified signature shows its error and never a signer: an identity it
claims is not a fact. Signatures and attestations that verified are listed
first.

### CI gate: `images signers --fail-on`

Exit code by verdict and level:

| Verdict | `--fail-on invalid` | `--fail-on unsigned` | `--fail-on unverified` |
|---------|:---:|:---:|:---:|
| `verified` | 0 | 0 | 0 |
| `key_signed` | 3 | 3 | 1 |
| `unsigned` | 0 | 1 | 1 |
| `invalid` | 1 | 1 | 1 |
| `unknown`, or no result | 3 | 3 | 3 |
| `verified`, but no signature names its signer | 3 | 3 | 3 |

| Exit | Meaning |
|------|---------|
| `0` | The verdict passes the level |
| `1` | The verdict fails it |
| `2` | The check could not run: the broker is unreachable, the port-forward or token failed, the broker returned an error, or a flag was invalid |
| `3` | The signature could not be verified: the digest has no result, its verdict is `unknown` (or one this CLI does not know), it is `key_signed` (a key kguardian was not given) below `unverified`, or it is `verified` but no signature names its signer (`no_signer_identity`, stored by an older broker). ## images trust

Calls `GET /image-trust`: the evaluator's
[ImageTrustPolicy](/concepts/image-trust-policy) and ClusterImageTrustPolicy
results, served by the broker. For every policy and running container it
selects: `Trusted`, `WouldDeny` or `Unknown` with the reason, `WouldDeny`
first. Report-only: `WouldDeny` means an admission controller enforcing the
policy would reject the image. kguardian never blocks anything.

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `-n, --namespace` | string | Only this namespace | all namespaces |
| `--kind`, `--name` | string | Only this workload, e.g. `--kind Deployment --name checkout` | all workloads |
| `--verdict` | string | `Trusted`, `WouldDeny` or `Unknown` | all |
| `--limit` | int | Results to print (max 2000). The counts always cover every result. | `200` |
| `--fail-on` | string | CI gate: `would-deny` | off |
| `-o, --output` | string | `table`, `json` or `yaml` | `table` |

| Reason | Meaning |
|--------|---------|
| `unsigned`, `invalid` | The image has no signature, or its signatures did not verify |
| `untrusted-signer` | Signed, but not by an identity or key the policy trusts |
| `key-not-verified` | Key-signed with a key kguardian was not given, and the policy trusts a key: give the supplychain component the key |
| `attestation-missing` | A required attestation is missing or not signed by a trusted signer |
| `not-checked` | No signature result yet (`Unknown`) |
| `namespace-unknown` | The namespace's labels could not be read (`Unknown`) |
| `broker-unavailable`, `broker-unauthorized` | The evaluator could not read signature results (`Unknown`) |

`Unknown` can also carry a discovery reason such as `registry_auth`, or
`no_signer_identity` (the result says verified but names no signer).

### CI gate: `--fail-on would-deny`

| Exit | Meaning |
|------|---------|
| `0` | Every selected container is `Trusted` |
| `1` | At least one `WouldDeny` |
| `2` | The check could not run: the broker is unreachable, the port-forward or token failed, a flag was invalid, or the broker has no image trust results (no evaluator, image trust evaluation off, the evaluator refused the token or could not be reached) |
| `3` | Unknown: at least one `Unknown` result and no `WouldDeny`, the evaluator has not finished a pass, or no policy selects the workloads |

The gate reads the counts, which cover every result, so `--limit` does not
hide a `WouldDeny`. `--verdict` cannot be combined with `--fail-on`.

```
$ kubectl kguardian images trust -n shop --fail-on would-deny
...
gate: 5 container result(s) would be denied (exit 1)

$ kubectl kguardian images trust --fail-on would-deny     # evaluator down
Image trust results are not available: the evaluator could not be reached: connection failed
Whether anything would be denied is unknown.
gate: could not check (exit 2): the evaluator could not be reached: connection failed
```

## images admission-policy

Calls `GET /attestations/policy` and writes an image signature admission
policy generated from the signers kguardian verified on running images
(needs `supplychain.signatureDiscovery.enabled`).

| Flag | Type | Description | Default |
|------|------|-------------|---------|
| `--format` | string | `kyverno` (ImageValidatingPolicy), `policy-controller` (ClusterImagePolicy) or `kguardian` (ImageTrustPolicy) | `kyverno` |
| `--mode` | string | `audit` or `enforce` | `audit` |
| `-n, --namespace` | string | Only images that workloads in this namespace run | all namespaces |
| `--acknowledge-partial` | bool | With `--mode enforce`: generate although some running images are not covered | `false` |
| `-f, --file` | string | Write to a file instead of stdout | stdout |

Audit is Kyverno `validationActions: [Audit]` with digest mutation off, or
policy-controller `mode: warn` (it has no audit-only mode). A repository is
covered only when every running digest of it verified; the rest are listed
in the header as not covered. See
[ImageTrustPolicy](/concepts/image-trust-policy#generating-policies) for what
is generated.

The policy is fetched whole before anything is written, and `-f` writes a
temporary file in the same directory and renames it over the target, so a
crash never leaves a partial file. If the broker's
answer is larger than the client reads (10 MiB), nothing is written and the
command exits 2 ("could not check") rather than leaving a cut-off policy.

```bash
kubectl kguardian images admission-policy -n payments > kyverno-images.yaml
kubectl kguardian images admission-policy --format policy-controller -f cip.yaml
```

```bash
# What runs in one namespace
kubectl kguardian images list -n payments

# Every deployed digest of one repository
kubectl kguardian images list --repository docker.io/library/nginx

# Which workloads still run an old digest
kubectl kguardian images get sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```
